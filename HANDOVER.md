## The honest status

**The engineering is solid. The product is getting there.** Four phases were built and
reviewed before the owner ever touched it; when they did, on 2026-08-01, the verdict was:

> "the UI and UX I see on this prototype is nowhere near as a native mobile application.
> Usability of the ideal functions and the UI UX are poorly designed to be properly used."

Milestones 1 and 2 answered most of that (a real APK, and the sessions redesign). The
**root cause is the lesson worth carrying**: progress was measured in tests passed and
review grades. 289 tests passed and a design review said B+ — neither measured *"would this
feel good to use"*, and no build reached the owner's hands for four phases.

That is why [`AGENTS.md`](AGENTS.md) §3 makes rendered verification mandatory and why the
emulator rig exists. Do not treat green tests as done.

## If you are not a Claude model

Nothing in the product requires you to be — but some of the *scaffolding* was built by
Claude-specific tooling. Translation:

| You'll see | What it means | What you do |
|---|---|---|
| `docs/superpowers/plans/`, `specs/` | Just markdown. Plan = numbered tasks for a milestone; spec = the design contract | Read and write them normally. Keep the naming convention `YYYY-MM-DD-<slug>.md` |
| `.superpowers/sdd/progress.md` | The ledger — one entry per task with commits and review outcomes | Keep appending. It is the project's memory of *why*, not just *what* |
| "subagent-driven development", "the rig caught it", "review round" | A process, not a product: implement a task, have a **separate context** review it, apply fixes, then move on | Reproduce the process with whatever your tool calls it. The separation is the point |
| `CLAUDE.md` | A one-line pointer to `AGENTS.md` | Add `GEMINI.md` / `.cursorrules` the same way if your tool needs one. **Never fork the guidance** |
| `.claude/launch.json`, `.gstack/` | Tooling config for the previous agent's harness | Ignore or delete; nothing depends on them |
| `@anthropic-ai/claude-agent-sdk` in `daemon/` | **This is the product, not the tooling.** The daemon drives Claude Code sessions on the PC | Keep it. Milestone 3 adds Codex *alongside* it, not instead |

Most of `.superpowers/sdd/` is deliberately gitignored — per-task briefs, review transcripts,
`review-*.diff` (git already has those diffs) and ~150 verification screenshots. Its
`.gitignore` allows back only the ledger, the decision write-ups and the current mockups. If
you clone this repo you get everything that matters and none of the noise.

## What does not travel with the repo

> ⚠️ **There is no git remote yet** — `git remote -v` is empty. Until the owner creates one,
> "the repo" is a single folder on one laptop and there is nothing to clone. See
> [`docs/roadmap.md`](docs/roadmap.md) → Open decisions.

Machine and account state a clone cannot reproduce — the owner has to redo these:

- **The pairing token** lives in `%APPDATA%\workbench\config.json` on OMEN16 and is generated
  per machine. Never committed, never logged.
- **The Android toolchain** (JDK 21, cmdline-tools, `ANDROID_HOME`, accepted licenses, the
  `workbench` AVD, `~/.gradle/gradle.properties` heap bump). See STATE → Prerequisites.
- **`cloudflared`** and, if it ever exists, the named tunnel's domain and credentials.
- **The owner's phone** with the installed APK, and their ntfy topic subscription.
- **`app/android/`** — generated by `expo prebuild`, gitignored on purpose. Every native
  setting must go through `app.json` or a config plugin or it evaporates on the next
  prebuild. This is how the `usesCleartextTraffic` fix was done; copy that pattern.

## First moves

1. Run both suites. Confirm 179 + 146.
2. Read STATE's "do not relitigate" list end to end. Several of those cost real days to learn
   — Tailscale, `0.0.0.0` on Windows, `process.on("exit")` and Ctrl+C, synchronous
   `killTree`, Android touch targets overhanging their parent.
3. Start **milestone 3** (`docs/roadmap.md`): Codex as the second agent, transcript history
   RPC, prepend-cwd fix.
4. Before you write app code, stand up the emulator rig once and confirm you can install and
   screenshot a build. It has caught two ship-blockers that no web render structurally could.

## Owner communication

ADHD-friendly, enforced: lead with the action, number the steps, bold the anchors, cap lists
at five, no preamble, no recap, one concrete next action. Full format in
[`AGENTS.md`](AGENTS.md) §6. They value honesty about what's broken over polish in the report.
